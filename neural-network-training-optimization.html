一次参数更新走对了，只是开始。这一篇接着回答：一场训练靠什么收敛，一个训好的模型靠什么便宜地跑起来。

前置阅读：《神经网络全景》第三节「训练是怎么发生的」（w ← w − η·∂L/∂w 与学习率三档）。 本页沿用同一套记号：w 参数、η 学习率、g 梯度。 所有显存与加速数字附换算式，可用计算器复核；前沿结论逐条给出论文出处。

如果你只有三分钟

  1. 优化器决定「往哪走」。AdamW 是稳妥的默认；Muon 把动量正交化，2025 年起在大规模预训练上把同等效果所需算力砍掉约一半，并已进入万亿参数级模型。
  2. 模型装不装得进显存，既是工程问题也是算术问题：精度（bf16/fp8）、激活检查点、分片（ZeRO/FSDP）、低秩微调（LoRA）各砍一块，本文给每一块的账。
  3. 部署是三级火箭：压缩（量化/蒸馏）→ 编译（算子融合/图优化）→ 服务（连续批处理/KV 缓存/投机解码）。vLLM 一类引擎把吞吐做到朴素实现的 20 倍以上。

一、一场训练的四个旋钮

前篇的仪表演示了「一步」怎么走。这一节先把「一场训练」的循环摆出来，再看每个环节分别由什么手段负责。

训练一个网络，就是把这个循环转上几千到几百万次：

训练循环（伪代码）  for batch in data:  g ← ∇L(batch; w)  →  w ← update(w, g, η)

四件事决定这场循环的成败：方向（优化器，把 g 加工成更好的步向）、步长（学习率及其调度）、纪律（正则化，防止把训练集背下来）、预算（显存与并行，决定多大的模型能开训）。循环结束拿到权重，问题才解决一半——把权重变成一个延迟、吞吐、成本达标的在线服务，是另一场工程。

旋钮负责什么失败时的样子本文章节
方向把梯度加工成更新量病态山谷里来回震荡，或绕远路二
步长每步走多远、怎么随时间变化发散、或一整天损失不动三
纪律约束容量，让验证集也受益训练损失一路降，验证损失回升三
预算精度、显存、卡数、通信Out of Memory，训练几天后崩四
部署时延、吞吐、单位成本离线指标很好，线上一秒一 token五
衔接

前篇用一维损失 L(w) = (w − 3)² 演示了「学习率三档」：太慢、恰好、发散。本篇把那座山换成二维、把那一个小球换成四种优化器同场竞速——见第二节的仪表。开篇窗口右侧监视器里的四条轨迹，就是竞速台的预演。

二、优化器：方向的进化

同一座山、同一个起点，不同的「方向加工器」走出完全不同的路径。先手工算三步，再上仪表。

动量：把历史坡度记下来momentum

朴素 SGD 只看脚下一步。动量法多记一个速度 v：每步把新梯度累进去、乘一个衰减系数，更新沿 v 走。一致的方向会累加，来回震荡的方向会抵消——这正好对症病态山谷（一个方向陡、一个方向平）：陡方向的震荡被抹平，平方向的推进被累加[1]。

v ← μ·v + g    w ← w − η·v

Adam：给每个参数配一把自己的尺子adaptive

Adam 为每个参数分别维护梯度的一阶矩 m（均值）和二阶矩 v（未开方的均方），更新量是两者之比[2]。直觉：m/√v 是一个「信噪比」——梯度一直同号说明方向可信，步子接近 η；梯度忽大忽小、忽正忽负，步子自动缩水。陡参数和平参数于是各走各的步长，这正是病态地形需要的。

第 1 步m₁ = 0.1×2.0 = 0.2v₁ = 0.001×4.0 = 0.004偏差修正前
修正m̂₁ = 0.2/(1−0.9) = 2.0v̂₁ = 0.004/(1−0.999) = 4.0√v̂₁ = 2.0
更新Δw = 0.1 × 2.0/2.0 = 0.100|g₁| = 2.0，步长却只有 η——自适应在起作用
第 2 步m₂ = 0.9×0.2 + 0.1×1.0 = 0.28v₂ = 0.999×0.004 + 0.001×1.0 ≈ 0.0050修正后 √v̂₂ ≈ 1.581
更新Δw = 0.1 × 1.474/1.581 ≈ 0.093梯度从 2 掉到 1，步长几乎不变——稳态下步长只看「信噪比」

Adam 把 L2 正则加进梯度，权重衰减会和自适应步长纠缠（衰减量随 1/√v 放大）。AdamW 把两者解耦：衰减直接按比例作用于权重，不经过梯度[3]。这是今天绝大多数训练的默认起点。

每步w ← w × (1 − η·λ) = w × 0.999衰减项独立于梯度
1000 步0.999¹⁰⁰⁰ ≈ e⁻¹ ≈ 0.368权重被压到原来的 37%——量级足以改变泛化

前沿：从「更好的一阶矩」到「正交化动量」2013 → 2026

2023 年以来的候选优化器都在动「更新量的形状」：

  • Lion（2023）把 Adam 的「比值」换成动量的符号，更新量只有 ±η，显存省一份动量，在大规模视觉与语言模型上与 AdamW 打平[4]。
  • Sophia（2023）给学习率除以梯度幅度的截断均方根估计，在 125M-770M 的 GPT 规模上报告同等损失所需计算量约为 AdamW 的一半[5]。
  • Schedule-Free AdamW（2024）把「训练中要不要衰减学习率」内嵌进优化器：用两份动量的插值替代调度曲线，省掉退火阶段的调参[6]。
  • AdEMAMix（2024）在快动量之外再加一份极慢（β₃ ≈ 0.9999）的动量，1.3B 模型用约一半的 token 数追平 AdamW 基线（3.7B 对 1.97B token）[7]。
  • Muon（2024-2025）作用于矩阵参数：把动量矩阵用 Newton-Schulz 迭代近似正交化（拉平奇异值），再以固定每坐标 RMS 放大。Moonshot 的 Moonlight 在 3B/16B 的 MoE 上验证：同等效果计算量省约 48%，显存状态省约 33%[8]；此后 Muon 系优化器进入万亿参数级预训练（Kimi K2，15.5T token）与 GLM-4.5 等模型。工程要点：矩阵参数用 Muon、嵌入与输出层仍用 AdamW，更新 RMS 对齐 0.2 并配合权重衰减。
边界

这些倍数都来自各自的论文设定。2025 年的两项独立基准把候选优化器与「认真调过参的 AdamW」对齐比较，发现多数优势会缩小甚至消失，AdamW 在超参鲁棒性上仍然占优[9][10]。合理的读法：Muon 的证据最强（有万亿参数级复现），其余按「值得在自己的任务上跑一组对照」对待。

三、步长与纪律：调度和正则

优化器定了方向，步长还要随时间变化；验证集表现则靠纪律维持。这两件事共享同一节，因为它们都在回答「训练后期怎么办」。

学习率为什么要「先热身后退火」warmup & decay

前篇的三档实验用的是一个恒定 η。真实训练几乎从不这样用。开局阶段 Adam 的二阶矩估计 v̂ 还没积累（手算块里偏差修正正是在补这个），梯度方差又大，大步长容易把权重推到坏区域——所以先线性升温几百到几千步。主体阶段用余弦或线性曲线退火：后期靠近极小值，步长必须缩小，否则损失在谷底两侧来回跳，永远落不下去。

η(t) = ηmax · tTwarm（升温）  →   ηmax · ½(1 + cos πt/T)（余弦退火）

批大小变了，学习率跟着变：线性缩放法则说，批大小乘 k、warmup 之后学习率也乘 k（梯度按批平均时方差不增、等效步长不变）[11]。同一条法则的另一面是梯度裁剪：批内出现异常样本导致梯度范数暴涨时，按全局范数截断（例如阈值 1.0），这一习惯同样来自大规模视觉训练[11]。

「训练得快」从来不是目的，验证集上的性价比才是。第五节的误区清单会回到这一点：把训练损失降到底，往往不是最好的那个检查点。

四、显存与并行：把训练装进硬件

到这一节，问题从数学变成算术：一个 7B 模型配 AdamW，显存账是每参数多少字节？砍价的刀有四把——精度、检查点、分片、低秩。

先算账：16 字节/参数从哪来memory math

参数 fp32 主副本7×10⁹ × 4 B = 28 GB更新用高精度
梯度 bf167×10⁹ × 2 B = 14 GB计算与通信用低精度
Adam 状态 m + v（fp32）7×10⁹ × 8 B = 56 GB两份滑动平均
合计（不含激活）28 + 14 + 56 = 98 GB≈ 每参数 14 B；纯 fp32 训练为 16 B → 112 GB

四把刀，各砍一块precision · checkpoint · shard · low-rank

精度。混合精度训练用 bf16/fp16 做前向与梯度，fp32 留给主权重与累加；fp16 还需要损失放大防止小梯度下溢[14]。再往下是 fp8：把激活与权重按块缩放存成 8 比特浮点，H100 一代硬件开始有原生支持[15]。DeepSeek-V3（671B 总参数/37B 激活，14.8T token）把按块 fp8 用到了全程预训练，2048 张 H800 上总耗时约 2.788M GPU 时[16]。2026 年的工作已经把 MoE 的专家权重训到 MXFP4（4 比特块缩放）精度[17]。方向明确：数值精度是显存与算力的兑换窗口，且兑换率在变好。

检查点重计算。不存全部中间激活，反向时按需重算：显存从「随层数线性」降为「随层数开方」，代价是约三分之一的额外前向计算[18]。这是「用时间换显存」的旋钮，长序列训练几乎必开。

分片。模型装不进一张卡，就把「参数、梯度、优化器状态」切开摊到 N 张卡上（ZeRO 的三个阶段逐级多切一样），用时聚合[19]；PyTorch 的 FSDP 是同一思想的原生实现。配合流水线并行与张量并行，就是「数据/张量/流水线」三维并行的完整训练栈。通信是分片的价格：卡间带宽不足时，扩展效率先于显存成为瓶颈。

低秩。微调时不动 7B 全量参数，只在注意力和前层旁边插入一对低秩矩阵 A·B（LoRA）[20]，可训练参数常不到 1%；QLoRA 再把冻结底座压成 4 比特 NF4，65B 模型微调进单卡 48 GB——对应图 2 第三行[21]。

算子层面的免费午餐fused kernels

注意力公式的数学不变，实现可以换：标准实现要把 N×N 的注意力矩阵写进显存再读回来，FlashAttention 改成分块计算、在线 softmax，注意力显存从 O(N²) 降到 O(N)；论文报告 16k 序列显存节省至 7.6×、BERT-large 训练端到端提速 15%、GPT-2（1k 序列）注意力提速 3×[22]；Hopper 架构上的 FlashAttention-3 借助异步与低精度 GEMM 再快 1.5-2×[23]。这类「同一数学、更快实现」还包括融合的 AdamW 内核、fused softmax 与 RMSNorm——它们不改变任何公式，只改变显存往返次数。

五、部署优化：从权重到服务

训练结束拿到检查点，离「一个延迟达标、吞吐够用、单位成本可接受的服务」还差一条流水线。压缩、编译、服务，三级各管一段。

压缩：量化、蒸馏、剪枝compression

训练后量化（PTQ）不改训练，拿现成权重直接压：GPTQ 逐列把权重投到 int4 网格、用海森矩阵修正已量化列的误差[24]；AWQ 的观察是约 1% 的「显著权重」决定精度，对它们所在通道做等比缩放保护，量化其余[25]；SmoothQuant 把激活里的离群幅度迁移到权重上，让 int8 的权重与激活都能量化（W8A8）[26]。量化感知训练（QAT）则在训练里就模拟量化算子，精度更高但要回训练循环。两条更老的路：蒸馏用大模型的输出当软标签训小模型[27]，剪枝按幅度或规则去掉不重要的连接再微调恢复[28]。

量化失真台quantization bench rig

一组模拟权重（4096 个样本，标准正态），分别量化到 bf16、int8（整张张量一个尺度）、int4（整张）与 int4（每 64 个一组一个尺度）。右图把「量化前 → 量化后」画成阶梯：台阶越稀，小权重被并成零的越多。打开离群值开关，几个 5-7σ 的样本会把整张量量化的格子撑大数倍——这正是 AWQ 与 SmoothQuant 要解的问题；分组量化是同一个思想的便宜版。

无离群，int4 整张Δ = 3.9/7 ≈ 0.56P(|x| < Δ/2) ≈ 22% 的权重变成 0；RMSE ≈ Δ/√12 ≈ 0.16（16% σ）
加了 ±6σ 离群Δ = 6/7 ≈ 0.86P(|x| < 0.43) ≈ 33% 变 0；RMSE ≈ 0.25（25% σ）

编译与引擎：同一数学，更快执行compile & engines

torch.compile 把 PyTorch 程序即时编译成融合内核的图，官方基准在常见负载上给出两位数百分比的提速，个别模型更高（以官方发布数据为准）[29]。推理侧的专用引擎把这套事做绝：TensorRT-LLM 针对 NVIDIA 卡做图优化与内核选择，ONNX Runtime 提供跨平台运行时，OpenVINO 面向 Intel CPU/核显。选型原则很朴素——固定硬件、固定形状、追求极限，用厂商引擎；跨平台交付，用 ONNX Runtime 一类中间层。代价是动态形状与自定义算子可能触发重编译，长尾场景要先测再选。

服务层：吞吐是拼出来的serving

自回归生成的每一步都要读全部历史的 K/V 投影。KV 缓存把它们留下避免重算，代价是显存：batch 越大、上下文越长，缓存越肥。架构层面的对策在训练时就埋下：MQA/GQA 让多组查询头共享少量 KV 头（例如 64 组查询共享 8 组 KV，缓存直接除以 8，质量几乎不掉）[30]；DeepSeek 的 MLA 把 KV 压缩进低秩潜在向量，缓存降到标准注意力的约 6.7%（论文口径 93.3% 削减）[31]。

批处理与调度是另一条线：连续批处理（Orca，OSDI 2022）让序列各自到位各自退出、新请求即时填空，而不是等整批凑齐[32]；PagedAttention（vLLM）把 KV 缓存按页管理，像操作系统管内存一样消除碎片，论文报告吞吐相对朴素 Transformers 推理最高 24×[33]。投机解码用小模型/草稿头先猜几个 token、大模型一次并行验证，接受的部分等于一步出了多步——数学上不改变输出分布，典型加速 2-3×[34]；2026 年的后续工作把「草稿器训练」也并进这条链路[35]。

收尾：五个误区

和前篇一样，以误区清单收尾。每一条都对应本页某个仪器或手算可以直接验证的事实。

  1. 「换了 Muon 就省一半算力。」

    48% 的节省来自 Moonlight 的 3B/16B 设定，且矩阵参数与嵌入层各用各的优化器、RMS 与权重衰减都要对齐。独立基准下，多数候选优化器对认真调参的 AdamW 优势会缩小[9][10]。先在自己的任务上跑对照，再迁移结论。

  2. 「量化必然掉点。」

    失真台显示：离群值才是 int4 的杀手，而整张量、分组缩放、激活迁移是逐级解药。int8 通道级量化在常见基准上的掉点常在 1% 量级；真正难的是权重与激活的联合分布，不是比特数本身。

  3. 「批越大越好。」

    批大小翻倍要学习率跟着翻（线性缩放法则[11]），超过某个点后泛化会变差、显存先爆；而小批配合梯度累积可以等效拼出大批，多一条腾挪的路。

  4. 「编译一次就一劳永逸。」

    图编译对静态形状友好，序列长度一变就可能重编译，延迟尖刺出现在线上而不是基准里。真实流量下先量：单步时延、重编译次数、长尾 P99，三个数一起看。

  5. 「推理优化是服务端的事。」

    KV 缓存的大小在训练选架构时就定了：GQA、MLA 是权重结构的一部分，事后没法给一个多头模型「加装」。部署成本的最优解，一半在训练前的架构选型里。

一页速记

优化器是方向的加工厂：动量抗震荡，Adam 按参数配尺子，AdamW 解耦正则，Muon 把矩阵动量正交化并已通过万亿参数级验证。步长先热身后退火，批大小动学习率跟着动。显存是算术题：fp32 主副本 + 梯度 + 两份矩 = 98 GB/7B，精度、检查点、分片、低秩各砍一块。部署是三级火箭：压缩减体积，编译提单步，服务层（连续批、KV 分页、投机解码）拼吞吐。所有倍数都要问一句：论文设定是什么，我的任务对得上吗。
