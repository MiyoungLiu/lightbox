规格卡上的七个数字

模型卡不是发布会的装饰，它是生产线的收据。七个数字分别由七段工序写下；读懂它们，就能判断哪些能力是买来的、哪些是训练阶段注定给不了的。

  1. 数据决定上限。去重、质量过滤与配比，比多抓一倍网页更值钱；数据截止日之后的世界，模型确实不知道（第 01 节）。
  2. 算力可以记账。训练浮点运算量约 6ND：70B 参数、1.4T token 约 5.88×10²³ FLOPs，40% MFU 下约 83 万 GPU·小时（第 02 节）。
  3. 基座不是产品。next-token 只优化“下一个词的概率”，不优化“这句话是否真实”；续写能力与指令遵循是两件事（第 03 节）。
  4. SFT 教格式，不教知识。指令微调把续写器变成对话体，偏好对齐再把多个可用答案排出先后；两者都改行为，不改参数里的世界知识（第 04–05 节）。
  5. 推理 RL 需要验证器。数学、代码、格式可以自动判对错，开放式诊断不行；没有验证器的领域，RL 很容易变成奖励投机（第 06 节）。
  6. 对齐有税，评测有污染。安全训练可能带来能力回退，公开榜单可能混进训练集；规格卡不写清楚，应用层就无法判断边界（第 07–08 节）。

先把七个数字与工序对齐。下表不是行业标准模板，而是一条可核对的因果链：字段写错，后面的评测与采购都会跟着错。

规格卡字段写它的工序它约束什么
参数量预训练配置容量、显存、单次推理成本；不是“越大越聪明”的线性保证
训练 token数据配比与训练预算知识密度、训练算力；与参数量共同决定 Chinchilla 口径
数据截止数据管线时效与知识盲区；截止后的指南、药名、政策只能靠检索补
上下文位置编码与长上下文训练单次可处理的证据量；不等于长期记忆
词表tokenizertoken 成本、多语言与代码效率；换词表要重训嵌入
对齐方法SFT / 偏好优化 / 推理 RL格式、拒答、语气、推理策略；不改世界知识
评测分评测集与评测协议可比性与污染风险；没有协议说明的分数不可比

下面按这条线走一遍。每一节只回答一个问题：这一段工序把哪个数字写进了规格卡，以及它给应用层留下了什么无法绕过的约束。

01

数据：网页到 token 的五道闸

预训练的第一步不是模型，是数据管线。清洗、过滤、去重、配比、tokenizer，每一道都改变模型最终知道什么；而 tokenizer 一旦定下，词表就冻结在模型之前。

五道闸：从原始网页到可训练语料

公开网页语料的原始体量以 PB 计，但直接喂给模型的是噪声、模板、重复与违规内容。生产管线通常要过五道闸，每一道都有明确的失败症状：

闸做什么跳过的后果
抽取正文抽取、语言识别、编码归一导航栏、页脚、广告模板进入语料，模型学会“网页腔”
质量启发式规则 + 质量分类器低质文本拉低整体分布，指令遵循与推理能力同步受损
去重精确哈希 + 近似去重（MinHash / SimHash）重复段落被反复记忆，评测分数虚高，长尾知识被挤占8
安全PII、毒性、版权与合规过滤隐私泄露、侵权与对齐阶段的额外负担
配比代码、数学、多语言、领域数据的比例与课程能力偏科；领域数据过量会挤掉通用能力，过少则学不会术语

质量与数量的取舍有公开证据：在精选的“教科书级”语料上训练的小模型，可以在部分推理任务上超过在原始网页上训练的大模型9。这条结论不能外推成“数据越少越好”，但它说明过滤与配比是乘数，不是装饰。企业自训时最常见的错误，是把内部文档一股脑倒进预训练，却不做去重、权限与时效治理——模型会把三份互相矛盾的旧制度同时背下来。

tokenizer：词表在模型之前就固定了

大模型不直接读字符，而是读 token。主流做法是字节对编码（BPE）：从字符或字节开始，反复把语料中最高频的相邻对合并成新符号，直到词表达到预设大小7。词表常见 32k–128k；英文大约 4 个字符一个 token，中文常见 1–2 个字符一个 token，代码与数字串往往更碎。

三个工程后果值得记住。其一，token 数决定成本：API 按 token 计费，上下文窗口按 token 计长，同一段中文在不同 tokenizer 下的账单可能差出一截。其二，词表先于模型：tokenizer 在预训练前训练好，换词表意味着重训嵌入矩阵与输出层，代价远高于换一个提示词。其三，分词边界会影响能力：数字、罕见术语、缩写如果被切得很碎，模型要花更多容量去拼回整体，这也是领域 tokenizer 存在的理由。

数据截止：模型不知道昨天

规格卡上的“数据截止”不是免责声明，而是能力边界。截止日之后发布的指南、药品说明书、政策文件，模型在参数里确实没有；它可能用旧知识流畅地回答，也可能编一个看起来合理的新版本。对时效敏感的任务，正确做法不是“再微调一下”，而是把新文档放进检索库，让答案带着出处进来。

边注 · 医学数据 医学语料还多两道闸：去标识化（DICOM 头、报告文本里的 PHI）与多中心偏倚（不同医院设备、协议、术语不一致）。如果 tokenizer 或数据管线跑在第三方 API 上，PHI 出域本身就是合规事件；能本地做的，不要外包。

数据段结束时，规格卡上至少写下了三个数字：训练 token、数据截止、词表大小。它们共同决定模型“知道什么”和“每知道一件事要花多少 token”。下一段是这些 token 被用来做什么。

02

预训练：next-token 与算力账

预训练只做一件事：在给定前文的条件下，最大化下一个 token 的概率。所有知识、推理与风格都从这一个目标里长出来；算力账单也从这个目标开始记。

目标函数：只学“下一个词”

给定 token 序列 x₁…x_T，模型学习条件分布 pθ(x_t | x_<t)，训练目标是最大化真实下一个 token 的对数似然，等价于最小化交叉熵：

L(θ) = − (1/T) Σt=1..T log pθ(x_t | x_<t)

这个目标没有“真值标签”，只有“语料里下一个词是什么”。因此模型学到的是语料分布，不是事实数据库：它可以把《内科学》的段落续写得像教科书，也可以在不知道答案时续写出一个语法完美、事实错误的句子。Transformer 的注意力结构让这一切可以并行训练1，但目标本身没有变。

scaling law：把算力换成 loss

规模定律给出了经验关系：在数据充足时，测试 loss 随参数量、数据量与算力呈幂律下降3。Chinchilla 进一步给出算力最优配比：在固定训练算力下，参数量与训练 token 应大致按 20 token / 参数 同步放大4。按这个口径，70B 模型应训练约 1.4T token。

但“训练算力最优”不等于“总成本最优”。如果模型要服务海量请求，推理成本会超过训练成本；此时故意把模型做小、把 token 训多（overtraining），反而能降低全生命周期成本。GPT-3 的 175B/300B 是另一个极端，token/参数比只有 1.72；Llama 2 70B 训练了约 2T token5；Llama 3 的 8B 与 70B 则都在约 15T token 上训练，token/参数比远高于 Chinchilla 的 20，就是这一取舍的公开样本6。图 2 把几个公开模型放到同一张图上：横轴参数量，纵轴训练 token，斜线是 20× 参考线。

算力账单：6ND 与 MFU

预训练的计算量有一个常用估算：前向与反向合计约 6ND FLOPs，其中 N 是参数量、D 是训练 token 数。这个式子忽略了注意力随序列长度的二次项与稀疏结构，但在千亿级稠密模型上量级够用。把 FLOPs 除以硬件的有效算力，就得到 GPU·小时；再乘单价，就是训练账单。

“有效算力”由 MFU（模型 FLOPs 利用率）描述：峰值算力乘 MFU 才是实际吞吐。大训练里 MFU 30–40% 是常见水平，50% 以上属于调得很好的工程；宣传口径如果只给峰值算力，账单会系统性地少算一半以上。

并行与失败：大训练不是一次跑完

单卡放不下千亿参数，训练必须并行：数据并行复制模型、切分 batch；张量并行把单层矩阵切到多卡；流水并行把不同层放到不同卡；序列并行切分长序列的激活。真实的大训练通常是几者组合的 3D/4D 并行，再叠加梯度检查点、混合精度与通信重叠。规模越大，硬件故障越频繁；一个千卡级任务跑几十天，中途重启几次是常态。规格卡不会写这些，但“训练成本”里已经包含了它们。

预训练结束时，模型已经拥有了大部分世界知识、语言能力与推理底座。规格卡上的参数量、训练 token、数据截止，到此全部写死。接下来所有工序都只改“怎么回答”，不改“知道什么”。

边注 · MFU MFU 不是越高越好：把 batch 拉大、序列拉长、通信压到最低，指标会好看，但可能牺牲收敛与稳定性。账单口径要同时写 MFU 与并行配置，否则两次“同样算力”的训练根本不可比。
03

基座：能力与缺陷是同一件事

基座模型的知识、幻觉、上下文能力与不听话，来自同一个训练目标。把它们拆开看，才能判断哪些能修、哪些只能绕。

参数里的知识：压缩，不是数据库

预训练把语料中的统计规律压进参数，而不是把原文存进一张表。好处是泛化：没见过的问题也能用相似结构回答；代价是不可寻址：你无法指出“这条知识存在第几层第几个神经元”，也无法像更新数据库一样只改一条事实。改一条知识，往往会牵动与它共现的其他关系；这就是“模型编辑”难以稳定落地、而检索增强更容易工程化的原因。

把模型称为“压缩”是一种有用的隐喻，但不要把隐喻当机制：训练目标并不是显式最小化描述长度，而是最大化下一个 token 的似然19。这也意味着，语料里反复出现的偏见、错误与过时信息，会和正确知识一起被压进去；数据治理的每一道闸，最终都会在模型行为里留下痕迹。

幻觉：目标函数的副产品

模型被训练成“给定前文，生成最可能的续写”。当它知道答案时，最可能的续写通常正确；当它不知道时，最可能的续写仍然是流畅的——于是它编。幻觉不是某一版模型的偶发 bug，而是目标函数没有“不知道就说不知道”这一项的结构性结果。SFT 可以教它说“我不确定”，偏好对齐可以惩罚编造，但都无法把“不知道”变成“知道”。

工程上的三道防线：一是接地，把答案限制在检索到的证据里，并要求逐句引用；二是拒答，证据不足时明确说不足，而不是给一个低置信度的猜测；三是输出校验，对数字、日期、实体做规则或二次模型检查。三道防线都不改模型参数，但都能把幻觉从“不可见”变成“可拦截”。

上下文不是记忆

上下文窗口是推理时的工作记忆：模型能在这段 token 内做注意力，但不会把它写回参数。把窗口从 8K 拉到 128K，不等于模型学会了长期记忆；它只是能在一次前向里看到更多证据。长上下文还有两个现实问题：中间遗忘——关键信息放在长文中间时，召回率明显低于开头与结尾20；成本——注意力随长度增长，长上下文的单次调用更贵、更慢。

因此“长上下文”与“检索”不是替代关系。证据少而固定，可以整段放进上下文；证据多、更新频繁、需要权限隔离，仍然要检索。RAG 篇把这条取舍拆得很细，这里只记结论：上下文解决“这一次能看到”，检索解决“下一次还能找到”。

基座不是产品

基座模型只会续写。你给它一个问句，它可能续写出更多问句；你给它一段代码，它可能续写出注释而不是可运行的程序。指令遵循、对话格式、拒答语气，都是后训练加上的行为层。把基座直接接进产品，最常见的失败不是“答错”，而是“不按你要的格式答”。

这张表解释了一个常见争论：幻觉要不要靠“更大的模型”解决？更大的模型通常更少幻觉，但不会归零，因为目标函数没变。真正可控的做法是把“不知道”显式建模进系统：检索不到就拒答，校验不过就回退，关键结论必须有人复核。

边注 · 医学事实 药品剂量、指南推荐等级、禁忌证属于高时效、高后果知识。模型参数里的版本可能滞后一两年；这类问题不要让模型“凭记忆”答，必须把最新版指南检索进来，并在答案里标出版本与日期。
04

SFT：把续写器变成对话体

监督微调（SFT）是行为克隆：给模型看成对的“指令—回答”，让它学会模仿回答的格式、语气与步骤。它能把续写器变成助手，但不会给模型增加新知识。

指令数据：质量、多样性、可验证性

SFT 的数据是 (prompt, response) 对。公开研究给过一个反直觉的起点：约 1000 条高质量、多样化的指令数据，就能把基座模型调到可用的对话水平17。这不是说 1000 条万能，而是说质量与多样性比堆量更早成为瓶颈：重复模板会让模型只会一种腔调，错误示范会被原样克隆。

生产上的指令数据通常来自四类来源：人工撰写、内部业务日志脱敏、强模型合成、以及拒绝采样筛选出的模型输出。四类都有风险：人工贵且慢；日志有隐私与偏置；合成数据会把教师模型的错误与风格一起蒸馏进来；拒绝采样需要可靠的判分器。SFT 数据表应至少记录来源、许可、去重方式与人工抽检比例。

loss mask：只学回答，不学问题

对话训练要把多轮对话拼成一条序列，并用 chat template 标出角色边界。关键细节是 loss mask：只在 assistant 的 token 上计算损失，system 与 user 的 token 置零。如果忘了 mask，模型会同时学习“怎样提问”，损失被大量非目标 token 稀释，训练效率下降；如果 mask 错位，模型可能学会在用户话没说完时抢答。

还有三个容易被忽略的工程点：打包（把多条短样本拼进一个长序列，注意别让后一条的注意力穿过前一条）、截断（长样本从哪一头截，决定模型看到的是开头还是结论）、模板一致性（训练与推理必须用同一套角色标记，否则格式迁移会失效）。

SFT 改什么，不改什么

SFT 改的是表达：指令遵循、输出结构、术语习惯、工具调用语法、拒答措辞。它不改的是参数里的世界知识：如果基座不知道某个新药，SFT 示范里写一百遍，模型也只是学会在类似问题里复述这个答案，换个问法就露馅。更糟的是，窄领域 SFT 过量会导致灾难性遗忘——通用能力回退，模型变得只会说训练集里的话。

缓解手段是数据混合：在领域 SFT 数据里掺入通用指令与一部分预训练语料（replay），并对通用能力做回归评估。SFT 不是“越专越好”，而是“在保持通用能力的前提下，把行为掰到目标格式”。

数据来源优势风险
人工撰写质量高、可控贵、慢、覆盖窄；标注者之间不一致
业务日志脱敏分布真实、覆盖长尾隐私、偏置、错误示范；脱敏不彻底会出域
强模型合成便宜、可规模化教师错误被克隆；风格单一；许可与蒸馏条款
拒绝采样只保留判分通过的样本判分器偏差决定数据分布；多样性下降

对医学影像团队，SFT 最合适的落点是报告格式与术语规范：结构化字段、测量值单位、阴性/阳性表述、模板必填项。这些是“怎么答”的问题，SFT 擅长。至于“这个征象代表什么病”，那是知识与推理的问题，应该交给基座能力、检索与临床验证，而不是指望 SFT 背下来。

边注 · 评估 SFT 后至少跑三组评估：格式合规率（schema 校验通过比例）、指令遵循率（ held-out 指令）、通用能力回归（防止遗忘）。只看训练 loss 下降，等于没评估。
05

偏好对齐：
从“能答”到“答得合意”

同一个问题有很多条都算正确的回答。SFT 只能模仿其中一条；偏好对齐学习的是“哪条更好”，把帮助性、诚实性与无害性排进输出分布。

为什么需要偏好：一个提示有很多好答案

指令数据里的“标准答案”只是众多可接受回答之一。偏好数据换一种问法：给模型同一个提示下的两个回答，让标注者判断哪个更好。成对比较比绝对打分更稳定，也更容易扩展；代价是需要定义清晰的标注指南，并处理标注者之间的一致性问题。偏好数据的质量，直接决定奖励模型与策略的上限。

RLHF：奖励模型 + PPO

经典 RLHF 分三步：先用 SFT 得到初始策略；再用成对偏好训练奖励模型（RM），让它给回答打分；最后用 PPO 优化策略，让高奖励回答的概率上升，同时用 KL 惩罚约束策略不要偏离参考模型太远101113。KL 惩罚是安全绳：没有它，策略会找到奖励模型的漏洞，输出人类并不想要的东西。

这套管线能力强，但工程复杂：RM 与策略要同时维护，PPO 对超参敏感，训练不稳定；奖励模型本身也会被“刷分”——策略越优化，RM 分数越高，真实质量却可能先升后降14。这就是 reward hacking，后文还会遇到。

DPO：把 RL 折叠成一个损失

直接偏好优化（DPO）注意到：在 KL 约束下，最优策略可以用奖励函数解析表示；把这个关系代回偏好损失，就不需要显式训练 RM，也不需要 PPO 的在线采样12。最终损失只依赖策略与参考模型在 chosen / rejected 两个回答上的对数概率比：

LDPO = − log σ( β · [ log(πθ(yw)/πref(yw)) − log(πθ(yl)/πref(yl)) ] )

β 控制偏离参考模型的强度：β 越大，策略被推得越狠；β 越小，越保守。DPO 的优点是简单、稳定、只需离线偏好数据；代价是它只优化“给定偏好对上的相对概率”，没有在线探索，容易过拟合偏好数据的分布，也需要关注 chosen / rejected 的长度偏差。

对齐改的是排序，不是能力

偏好对齐能让模型更愿意帮忙、更少输出有害内容、语气更符合产品，但它不增加知识，也不保证事实正确。更麻烦的是对齐税：安全训练可能让模型过度拒答，或在某些通用能力上回退；偏好数据里的长度偏好会让回答越来越长；标注者的口味会被放大成模型的风格。上线前要用三类评估夹住：目标行为、通用能力、以及对抗性红队。

边注 · 对齐税怎么量 同一套评测要在 base、SFT、偏好对齐后各跑一遍；只看目标指标，会漏掉通用能力的回退。安全拒答率上升、回答变长、代码通过率下降，都是税单上的项目。

偏好对齐之后，模型的“默认回答”已经接近产品想要的语气与边界。但它仍然是一个一次生成一个 token 的模型；面对需要多步推理的问题，它可能一步走错就整段跑偏。下一节的推理强化，专门训练“想久一点”。

06

推理强化：用可验证奖励教“想久一点”

偏好对齐教模型“哪种回答更讨喜”，推理强化教它“哪种推理能算对”。后者的关键不是更大的模型，而是有一个便宜、稳定、可扩展的验证器。

从偏好到验证器

偏好数据需要人来判断“哪个更好”，成本高、主观性强。推理强化换了一条路：只给提示，不给示范，让模型自己采样多个回答，再用可验证奖励判对错。数学题可以核对最终答案，代码可以跑单元测试，结构化输出可以用 schema 校验，格式任务可以用规则匹配。这类做法通常称为 RLVR（Reinforcement Learning with Verifiable Rewards）。

它把监督信号从“人类偏好”换成了“程序判定”，于是可以大规模采样、自动打分、反复训练。代价是奖励的覆盖面：验证器只认它检查的那一部分，模型会学会在检查点上拿分，而不是在检查点之外变好。这就是后文 reward hacking 的入口。

GRPO：去掉 critic

PPO 需要一个与策略同规模的价值网络（critic）来估计基线，显存与工程成本都高。GRPO 的做法更轻：对同一个提示采样一组回答，用组内平均奖励作为基线，算每个回答的相对优势，再更新策略15。省掉 critic 后，同样的卡可以跑更大的策略或更大的 batch；代价是组内比较的方差、以及采样成本。

DeepSeek-R1 的公开报告展示了这条路线的一个极端版本：先不做 SFT，直接在基座上用可验证奖励做 RL，模型会自发长出更长的思维链、自我检查与回溯；但也会出现可读性下降、语言混杂等问题，所以最终系统仍然加入了冷启动 SFT 与多阶段训练16。这说明“纯 RL 涌现推理”不是免费的：奖励设计、数据课程与后处理仍然决定可用性。

长思维链的代价

推理 RL 的直接后果是输出变长：模型学会在给出答案前写更多中间步骤。长思维链在数学与代码上确实能提升正确率，但它把成本从训练转移到了推理——每个请求多几百到几千个 token，延迟与账单同步上升。更隐蔽的问题是长度膨胀：如果奖励只看正确率，模型可能学会用更长的篇幅碰运气；如果奖励里加入长度惩罚，又可能压制真正需要的推理。

图 4 是 reward hacking 的经典形态：优化压力越大，代理奖励（proxy）单调上升，真实质量却先升后降。最佳停止点不在曲线末端，而在两条线的差距开始扩大之前。工程上对应的是早停、KL 约束、定期人工抽检，以及把“真实质量”做成独立的评估集，而不是继续看训练奖励。

没有验证器的领域怎么办

开放式写作、咨询建议、影像诊断都没有便宜的自动判分器。可选路径有三条：过程奖励模型（对中间步骤打分，成本高且本身可能被刷）、规则化评分（把可检查的部分抽出来，如引用是否可回查、单位是否正确、格式是否合规）、人在回路（小规模高质量偏好，而不是大规模自动奖励）。三条路都不是“纯 RL”，都需要把人类判断重新放回管线。

对医学影像，先分清两类任务：可验证的（测量值抽取、报告结构化、单位换算、指南条目匹配）可以走 RLVR；不可验证的（诊断结论、治疗建议）不适合用自动奖励硬训，应该走检索、证据引用与临床评估。把不可验证任务包装成可验证指标，是医疗 AI 最常见的自欺。

到这里，模型已经走完“预训练—SFT—偏好—推理 RL”四段。它知道很多、会按格式答、知道什么不该说、也会在可验证任务上多想几步。但它仍然会犯错，而且这些错误在评测与部署阶段才真正暴露。

边注 · 长度膨胀 推理 RL 后，回答长度可能翻倍。上线前要同时看正确率、平均输出 token、P95 延迟三条线；只看正确率，会把账单和延迟一起漏掉。
07

对齐的代价与评测的边界

对齐不是免费的：安全训练可能带来能力回退，公开分数可能被污染，开源权重也可能来自蒸馏。规格卡如果不披露这些，应用层就在雾里做采购。

对齐税：安全与能力的拉扯

InstructGPT 的公开结果已经提示过对齐税：RLHF 后模型在人类偏好上大幅提升，但部分公开 NLP 基准出现回退10。后续工作用数据混合、参数高效微调、在线评估等手段把税压低，但没有把税消掉。典型症状是过度拒答：模型把正常的医学问题当成高风险问题拒绝，或者用一段免责声明替代实质回答。

对齐税要用三层评估夹住：目标行为（帮助性、拒答率）、通用能力（推理、代码、多语言）、对抗性红队（越狱、提示注入、诱导编造）。只报“安全分提升”而不报“能力回退”，等于把成本藏起来。

评测污染：分数可能来自训练集

公开基准的题目可能出现在预训练网页、SFT 合成数据或偏好数据里。GSM1k 的复现实验显示，把题目做轻微改写后，部分模型的数学准确率明显下降，说明原分数里混有记忆成分21。污染不一定来自故意作弊；数据管线规模太大，去重不可能覆盖所有基准的变体。

工程上的对策：按时间切分评估集（用截止日之后的题）、做 n-gram / 嵌入近邻污染检测、保留 canary 字符串、在规格卡里写清“评测集版本与污染检查结果”。榜单分数如果不附这些信息，只能当广告，不能当验收标准。

蒸馏血统与开源透明度

许多“开源”模型只开放权重，不开放数据与训练配方；部分模型的训练数据包含更强模型的合成输出。这不一定是问题，但会影响三件事：许可（教师模型的条款是否允许蒸馏）、可复现性（你无法重训，只能接受发布者的评测）、能力归因（模型的能力来自数据、架构还是蒸馏，外部无法拆开）。采购时要区分“开放权重”“开放数据”“开放配方”三种开放程度，它们对应的风险完全不同。

规格卡不是法律文件，但它是应用层的合同：写清楚“不知道什么、不能做什么、分数怎么来的”，团队才能决定哪些任务交给模型、哪些必须检索、哪些必须人工复核18。下一节把这张卡收成一页，并落到医学影像团队的三条具体含义。

边注 · 采购清单 医学影像采购至少追问五件事：数据能否不出院、模型能否本地部署、版本能否锁定、评测能否在自建集上复跑、更新后的回归门禁谁负责。这五问比榜单排名更能决定项目成败。
08

收束：把规格卡当合同

模型不是从发布会里长出来的，是从数据、算力与偏好数据里长出来的。规格卡把这条生产线的结果写成可核对的字段；应用层的每一个设计决定，都应该能回指到其中一个字段。

能力溯源矩阵

图 5 把“应用层想要的能力”与“哪段工序能提供它”放在一张矩阵里。实心圆表示主要来源，空心圆表示次要影响，横杠表示基本无关。它的用途是防止两类错误：把知识问题当成格式问题去微调，或者把格式问题当成知识问题去换模型。

对医学影像团队的三条含义

第一，微调加不了新知识。新指南、新药名、新政策属于参数外知识，正确路径是检索与证据引用；SFT 只负责把报告格式、术语与字段规范教给模型。把新知识写进 SFT 示范，短期看似有效，换一个问法就会暴露。

第二，版本升级会破坏提示词与报告模板。偏好对齐会改变默认语气、拒答边界与输出长度；同一个提示词在新版本上可能从“简洁结论”变成“长篇免责声明”。上线前要锁版本、保留 golden set、做逐版本回归；升级不是换一个 API 名称，而是一次行为变更。

第三，数据脱敏与去重决定能不能自训。院内数据涉及 PHI、多中心协议差异与数据使用许可；如果去标识化不彻底，tokenizer 或训练管线在第三方环境跑一遍就是出域事件。能本地做的预处理不要外包；能检索解决的知识不要靠自训；真要自训，先把数据治理与评估集做出来，再谈算力。
