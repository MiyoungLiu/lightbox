00

范围与主要结论

OVERVIEW

先把结论放在最前面：能力边界、杠杆制约、需求真伪、指标体系——这一页的四条主线。

  1. 大模型是条件概率引擎，不是知识库。生成流畅文本的能力远强于对事实自检的能力； 幻觉不是缺陷，是逐 token 采样机制的内生副产品4。 产品形态由「输出可验证性 × 出错代价」决定，而不是由模型参数量决定。
  2. 三个杠杆各管一段，顺序不能反。提示词改行为（分钟级迭代）、RAG 注知识（小时到天级）、 微调塑风格（周级）。用微调去记知识是最贵的知识更新方式，也是最常见的误判。
  3. 向量检索解决「换个说法就找不到」，但把瓶颈搬到了召回质量。语义检索的上线口径是 recall@k 与引用命中率，不是「演示时看起来合理」。
  4. 真需求长在高频、容错可界定、失败有兜底的工作上。补全、检索、改写先落地， 是因为它们天然满足这三条；决策链与责任链上的环节（诊断、定价、架构决策）现阶段只能做辅助。
  5. 伪需求的共同形态是「技术找场景」。判据很朴素：去掉 AI 之后用户的替代成本有多高、 失败一次的代价多大、有没有人愿意为效果负责。
  6. 指标决定选型与体验。召回率／准确率管质量上限，TTFT 与每 token 延迟管体感， token 成本管商业模型能不能算过来，上下文长度看有效值而非标称值——后者通常短得多11。
01

生成与理解：大模型的能力边界

BOUNDARY

把模型看成一台条件概率引擎之后，「会不会写」就不再是问题——问题变成「错了能不能发现」。

机制：逐 token 的条件概率

大模型只做一件事：在给定上下文里预测下一个 token，采样、拼接、再预测，直到结束。Transformer 自注意力1让这个分布能吃下长上下文；GPT-3 把参数推到 175B 后，关键现象出现——不更新任何权重，只在提示里给几个示例，模型就能照做新任务（少样本学习）2。

指令微调加人类反馈再进一步：2022 年的实验里，13 亿参数的 InstructGPT 在人类偏好评测中胜过了 1750 亿参数的原版 GPT-33——「听话」与「大」是两个独立的轴：对齐质量直接决定可用性。

机制给出两条产品推论。其一，输出是采样出来的：同一个问题问两遍，答案可能不同；调低温度只能让它更稳，不能变成查表。其二，参数知识是训练截止日的静态快照：不会自己更新，也不知道自己不知道什么。

强在生成，弱在自检

生成侧的能力是实打实的：风格迁移、改写、长文摘要、结构化提取（把一段话变成 JSON）、多轮对话、代码补全——2021 年 Codex 在 HumanEval 上已通过约 72% 的题目8，四年后这条曲线接近饱和（第 05 节）。共同点是评价标准为「通顺、合理、像不像」，而非「每个字都真实」。

边界同样是结构性的，至少四条：

  • 事实性。训练语料里的知识被压进权重，检索不到就靠概率「补全」， 补出来的引用、数字、条款可以完全虚构。幻觉是自然语言生成里被系统研究的现象， 不是某个版本的 bug4。
  • 符号运算与计数。数字与字符在分词阶段被打碎，长链算术、精确计数、字符串位置 这类任务交给模型直算不可靠——该用工具（解释器、计算器、代码）的场景就不要让模型心算。
  • 长上下文的一致性。窗口标称越长，中间越容易被忽略：相关材料放在上下文中部时， 准确率显著低于放在首尾10；用更难的合成任务系统测量， 多数模型的有效上下文明显小于标称值11。
  • 自我校验。模型无法从内部区分「记得」与「编得」，让它自评置信度并不提供担保。 可靠性必须来自外部：引用、检索证据、测试或人工确认。
一个数字

2023 年《Nature》论文里，通用模型 Flan-PaLM 在医师执照风格题库 MedQA 上拿到 67.6%，指令微调后的 Med-PaLM 在人类评测中反超通用模型15。但选择题 ≠ 问诊：追问、责任与随访都不在题库内。考试分数只衡量第 1 节说的「封闭式作答」，产品面对的是完整的能力地图。

边界的产品含义

能力边界划的不是「能不能用」，而是「怎么用」。输出可被程序验证的任务（编译、测试、执行 SQL）适合自动化，错了机器自己会发现；无法自动验证、错了代价又高的任务（事实陈述、专业建议），必须把模型从「答题者」降为「起草者」——给引用、草稿、diff，终审留给人。后面三节的杠杆、检索与场景，都是在移动任务在地图上的位置，而不是抹掉地图。

02

提示词、RAG、微调：三个杠杆及其制约

LEVERS

三个杠杆的分工是：提示词改行为、RAG 注知识、微调塑风格。顺序用反，成本翻倍还不讨好。

提示词工程：优先使用成本最低的杠杆迭代 · 分钟

指令、角色设定、少样本示例、输出格式约束（JSON schema、正则、枚举），不更新权重就能改变模型的行为面。制约恰恰来自便宜：效果脆弱——换个同义说法、调一下示例顺序，输出就可能漂移；提示词越长，上下文预算越紧；它也没有类型系统，回归只能靠评测集。工程上要把提示词当代码资产：版本化、带测试用例、变更走评审。

RAG：把知识放回数据库迭代 · 小时至天

检索增强生成（RAG）的思路 2020 年已成型：生成前先检索相关文档，把片段拼进上下文，让模型「开卷作答」5。它换来三样东西：知识随时更新（换文档就行）、答案可溯源（给引用）、内容可撤销（下架文档即生效）——微调都做不到。代价是「调 API」变成七段管线，每段都有自己的失败模式：

微调：改「说话方式」，不是「记住事实」迭代 · 周

低秩适配（LoRA）把微调成本压到消费级显卡可承受的范围6，但成本大头不在算力，在数据工程：标注、配比、去污染、评测集构建。微调擅长固定的「领域语感」与输出版式——病历段式、工单口径、客服话术禁区；不擅长注入事实：易变知识写进权重，更新就要重训，还可能因灾难性遗忘丢掉原有能力。

常见误判

「用微调让模型记住公司知识」，是把数据库的活派给快照。价格表下周就变，微调周期以周计；文档库更新以分钟计。知识放检索库，行为放提示词，只有「风格与格式」值得写进权重。

03

语义检索：从关键词到向量

RETRIEVAL

向量检索解决「换个说法就找不到」，但把系统的可靠性瓶颈从生成搬到了召回——这是一笔要认的账。

词面匹配的两类失效

传统搜索把文档与查询拆成词项，靠字面重合排序，有两处系统性失效：同义不同词——「住宿的钱找谁报」对上「差旅费报销」，公共词项几乎为零；同词不同义——「苹果手机碎屏」与「苹果膳食纤维」字面相似，语义却相远。两类失效在企业知识库、工单、法规检索里极高频，这正是嵌入模型的位置。

两段式检索：先保召回，再管精度

工程上的语义检索几乎都分两段：向量库用近似最近邻（ANN）从百万级文档粗召回 top-k，交叉编码重排模型再对几十条精排。ANN 用一点召回换数量级的性能，重排用只看几十条换更准的顺序。产品要盯两个指标：recall@k 决定答案在不在候选里，precision 决定上下文的干净程度——后者同时影响生成质量与 token 成本（定义与仪器见第 08 节）。

三个应用位

  • 内容生成：先检索，再生成。写文案前检索品牌素材与合规表述，写代码前检索内部 API 与既有实现（这正好是第 05 节编程 Agent 的骨架）。检索提供「接地」，生成提供「组装」。
  • 用户交互：意图路由与语义缓存。把用户请求分类到 FAQ、工单、人工或 RAG 通道， 是分类问题而非生成问题，小模型即可；相似问题命中历史答案的语义缓存， 把高频问答的延迟与成本压到缓存读写一级。
  • 智能问答：企业知识库。问答只是入口，产品价值在「答案带引用、引用可点开、 点开是原文」——引用既是信任界面，也是幻觉的对照证据（见第 02 节图 3 的最后一段）。
工程边界

嵌入模型对领域黑话、中英混排、缩写敏感，通用嵌入在企业语料上掉点是常态。上线前用自己的查询建评测集（几百条真实问题 + 人工标注的相关文档），按 recall@k 分层盯：高频问题必须高分，长尾决定口碑。嵌入换版本要重建整个向量库——一次性成本，但得在架构里预留。

04

多模态：接口在变，可靠性模型没变

MULTIMODAL

多模态把大模型的输入输出从文字扩展到文档版面、图像、语音——它改变的是接口，不是第 01 节那张能力地图。

输入侧与输出侧

输入侧三类能力已经商品化：文档理解（版面分析、表格还原、手写识别）、图像与视频理解（视觉问答、图表读数、缺陷目检）、语音理解（识别加语义处理）。输出侧是文生图、语音合成、视频生成。产品价值最高的组合往往不是「生成多惊艳」，而是「非结构化输入 → 结构化输出」：拍票据得报销字段、拍仪表得读数、拍白板得任务卡。

三个应用位

  • 内容生成：按文案语义检索配图与封面、生成插图初稿、语音合成配音——生成环节解决「从无到有」， 检索环节解决「与品牌一致」。多模态在这里的组合价值大于单一模型能力。
  • 用户交互：截图直接提问（把「描述问题」变成「给看问题」）、语音入口、 拍票据 / 拍仪表自动结构化。交互门槛被大幅拉低，这正是移动端场景最先吃到红利的原因。
  • 智能问答：图表问答（「这张折线图哪个月拐点」）、扫描件与 PDF 问答、 视频内容定位。答案口径同样要给引用——引用到页码、到时间戳。
边界

模态 ≠ 智能。版面错一格、OCR 错一个数字，错误就顺管线向下游传播且不报警——与事实性边界同构，只是更隐蔽。复杂图表（双轴、合并单元格、跨页表格）仍是高发失效区；生成侧还要面对版权与形象一致性。多模态同样适用那张能力地图：可验证的（字段抽取、读数对照）往前放，不可验证的（图像诊断结论）留在人工确认后。

05

场景盘点：办公、搜索、知识管理、编程

SCENARIOS

判断顺序固定：先看用户的痛点是什么，再看大模型与 Agent 能接到哪一层，最后看失败模式有没有兜底。

编程：从补全到「领任务」最先落地

编程是 AI 落地最深场景，原因是结构性的：反馈环闭合——编译、测试、运行就是天然的验证器， 第 01 节地图里它整个落在右侧「工具兜底区」。

轨迹最有说服力：2021 年 Codex 在 HumanEval 上通过率约 72%8；2023 年 SWE-bench 换成真实 GitHub issue，最好系统解决率不足 5%9；到 2026 年 11 月，公开榜首已在 95% 上下，基准接近饱和，更难的变体（更长仓库、更少提示）成为新分水岭17。三年从 5% 到 95%，前提恰恰是「错了机器自己知道」。

边界同样清楚：架构决策、需求对齐、安全审计没有自动验证器，依旧靠人。Agent 的合理定位是受验证器约束的执行者：领一个 issue，检索代码、改文件、跑测试、按结果迭代，交一个带测试证据的 PR——对不对、合不合，责任仍在评审者。

办公：起草与整理是真需求

办公场景的价值集中在两类：把「从零起草」变成「从草稿改」——邮件、方案、汇报的组织成本被砍掉一截；把「非结构化转结构化」——录音转纪要并提取行动项、表格清洗、公式与透视建议。纪要→行动项是高频真需求：错误代价低、人工可快速核对。反例是「一键生成周报」：写不是瓶颈，读才是——没有读者的自动化，只是把空白文档换成生成的文档（第 07 节展开）。

搜索：从链接列表到带引用的答案

搜索的产品形态正从「给十条链接自己拼」转向「直接给带引用的答案」，内核是第 02 节的 RAG。胜负手不在生成，在引用可信：每个关键事实能否落到一条可点开的来源。搜索也是语义检索的大众化教室——用户已经接受「换个说法也能搜到」。商业约束（订阅还是广告）会反过来塑造答案形态，这是产品约束影响技术选型的例子。

知识管理：问答只是入口

企业知识库的真痛点不是「没有文档」，是「写了没人看、搜索找不到、新人上手慢」。问答入口加「答案定位到原文段落」能同时缓解三者，但有三条硬前提：权限——检索层必须带访问控制，问答入口不能成为越权阅读的旁路；知识腐化——过期文档比没有更糟，答案要带时间戳与责任人；冷启动——垃圾进垃圾出，未治理的语料只会产出自信的错误答案。RAG 产品表面是 AI 问题，底下是知识治理，后者常占七成工时。

06

领域痛点：四个视角，不是四个行业

DOMAINS

四个领域不是并列行业，而是四种场景透镜；先划各自的边界，再把它们摊成一张企业能力 × 医院工作流的价值地图。

代码 遗留系统无文档；测试覆盖率低；评审疲劳；重复工单消耗 代码解释与检索；测试生成；跨语言迁移 PR；工单自动归类 需求与实现的对齐；跨团队架构决策；安全审计终审

医疗是「能力」与「允许」差距最大的领域。通用模型在医师执照风格题库上早已越过及格线15，临床综述的判断却是：大模型更现实的近期位置是扩展医生的能力与带宽，而非取代判断16。翻译成产品是三件事：写在医生出的草稿上、检索在医生定的文献里、决策留在医生手上。责任链不动，AI 只做其中可验证的几节。

从领域清单到价值地图医疗影像

一个医疗影像企业同时穿过这四种透镜：算法与产品、集成与工作流、交付与服务、法规与质量、 商业与证据。医院侧则按检查前、检查中、 检查后、管理与质控展开；把两侧交叉，才能看到 AI 真正能接住的格子。

企业能力层医院工作流触点典型痛点AI 能接住人必须保留价值指标
算法/产品 阅片、诊断 跨设备与协议泛化、伪影、工作流不匹配 质控、预筛、量化、病灶追踪 诊断签字与责任 阅读时间、诊断一致性

这张表的读法是从左到右：AI 的介入点越靠近医院工作流，价值越具体，责任与监管也越重。 「离医院更近」因此不是把模型做大，而是四级台阶：卖算法 → 卖集成 → 卖工作流结果 → 卖持续运营与证据。AI 压低的是每一级台阶的成本——接口映射、文档、现场知识、证据汇总； 跨台阶的障碍是信任、责任与组织流程。

可视化软件的真需求以本行为例

医学影像可视化软件的价值不是「渲染得更炫」，而是让医生更快到达可操作的图像与测量。 最贴近产品的三个切入点：

  • 智能预检 + 初始视图。加载前检查方向、间距、序列完整性、期相与伪影，自动选择布局、 窗宽窗位与初始相机；指标是首张有用图像时间与点击次数。
  • 可编辑分割/中心线 + 一键量化。分割、中心线、landmark、多模态与随访配准， 结果必须可编辑、可回退、留痕；指标是编辑时间、Dice/HD95 与测量重复性。
  • 关键图像/视频包 + 渲染 QA。自动编排 MDT 与报告用的关键图、电影、3D 快照； 渲染回归用 golden image 与感知差异兜底；指标是准备时间与视觉回归逃逸数。

反过来，生成式「补解剖」、未验证的超分/去噪直接进诊断链、全自动分割不允许编辑， 都是失败不可兜底的伪需求。

四个视角摆在一起还能看到一个规律：AI 能接住的层大多是「输入输出可验证」的环节； 碰不了的层，几乎都是「责任与政治」。这不是模型能力问题，是组织问题——把这条规律用在需求评审上， 比任何模型榜单都有用。

07

伪需求识别与「不重复造轮子」

PSEUDO-NEEDS

伪需求不是「用户不想要」，是把「技术能做到」当成了「有人需要」；轮子要不要造，取决于护城河在哪一层。

什么是伪需求

判据只有一句：去掉 AI，用户的替代成本有多高。手写两分钟就能填的表，不值得一个每天可能答错的产品；每周要花两小时整理的纪要，哪怕只有 80% 准确率，人工校对十分钟也划算。真需求四个条件缺一不可：高频、痛点深、失败可兜底、效果可度量。「用户喜欢和它聊天」不在其中——用户要的不是对话，是把事办完。

六个识别信号

  1. 演示惊艳，留存趋零。尝鲜一次就不再回来，说明惊艳的是技术不是价值； 看次日 / 七日回访，不看发布会掌声。
  2. 替代成本很低。关掉这个功能，用户手动完成只要一两步——那它只是一个不太稳的快捷键。
  3. 失败不可接受，又没有兜底。错了不能改、不能撤、看不出错——需求可能是真的， 但当前形态不成立，先做检测与确认流。
  4. 评测只有演示案例。问失败率答不上来、没有标注集、没有回归口径—— 「看起来能用」和「可以上线」之间隔着一套评测。
  5. 描述用「加上 AI」句式。「在 X 上加上 AI」是供给视角；「把 X 的某指标从 A 做到 B」才是需求视角。
  6. 没人吃自己的狗粮。团队内部都不在日常用它——第一个最真实用户的流失，通常已经发生完了。

需求五问（评审可直接用）

  • 用户现在怎么解决这个问题？花多少时间？
  • AI 方案快多少、好多少——量化，不形容。
  • 错了怎么办：谁发现、怎么改、代价多大？
  • 高频还是低频？低频场景的获客与留存各自怎么算？
  • 谁为效果负责：出错的锅在模型、在产品、还是在流程？

不重复造轮子：三层评估

「造轮子」的冲动通常来自低估了已有设施的成熟度。评估按三层走：

层先问：现成的够不够什么时候自己建
模型层 API 直接调（旗舰／入门档按任务难度路由）；开源权重自托管（数据不出域时） 领域分布与通用模型差异巨大、且已证明是效果瓶颈时
框架层 编排、评测、观测用开源与成熟服务；提示词版本管理、轨迹回放都有现成件 几乎不需要自建——自研中间件的维护成本常高于省下的授权费
数据层 嵌入与重排直接用模型服务；向量库按规模选型 评测集、标注口径、领域语料——这是真正的护城河，必须自建

判断式很朴素：数据敏感、规模成本拐点、核心差异化，占其一才考虑自建；都不占就用现成的，把工程时间花在评测集与数据飞轮上。榜单是公共的（第 08 节讲它与真实任务的差距12），胶水代码可复制，只有「自己的任务分布 + 标注 + 反馈闭环」复制不走。

反例清单

「全知企业助手」——权限与责任无处安放，一上线就是合规事故温床； 「一键生成高管报告」——读者不存在，写作从来不是瓶颈； 「门面聊天机器人」——三句之后转人工，入口却假装智能，只会训练用户绕开它。 三者的共同点：只回答「技术能做什么」，没回答「谁的问题被解决」。

08

指标体系：召回、延迟、成本与上下文

METRICS

指标不是汇报用的报表，是选型与体验的决策变量：质量定上限，延迟定体感，成本定商业模型，窗口定架构。

质量类：召回率与准确率

检索与生成的质量口径都从混淆矩阵出发。对一次检索：相关且被检回的是 TP， 检回但不相关的是 FP，相关但没检回的是 FN。由此得到两个不能互相替代的率：

recall@k = TP / (TP + FN)　——该找到的，找到了多少
precision@k = TP / (TP + FP)　——找到的里面，多少是真的

两者分工明确：recall@k 决定「能不能答」——金标准不在候选里，生成再强也无力回天；precision 决定「上下文干不干净」——噪声既拉低生成质量，又白耗 token。另有一个命名陷阱：中文「准确率」在不同团队分别指 accuracy（全对比例）与 precision（精确率），评审前先对齐口径。下面这台检索台用 12 条迷你语料逐项量化：

    延迟类：TTFT 与每 token 延迟

    生成是逐 token 串行的，所以延迟拆成两段看：TTFT（time to first token，首 token 延迟） 决定用户何时「看到它开始回答」，每 token 生成延迟（TPOT，其倒数即 tokens/s）决定 长答案要等多久。

    流式的本质是把 TTFT 提前暴露给用户——交互领域的经典口径是 0.1 秒内无感、1 秒内思路不断、10 秒后注意力流失；TTFT 压进 1 秒是体验底线，长输出靠 tokens/s 撑住。

    报表口径用 P50／P95／P99：平均值会撒谎，P99 才是刷走用户的请求。工程侧加速——投机解码约 2–3 倍14，连续批处理与 PagedAttention 把吞吐做到 2–4 倍13——细节见本站《神经网络训练优化》部署篇。

    成本类：输入输出分开算的账

    token 计价分输入、输出两档，输出显著更贵：它要逐 token 串行计算，输入则可以并行预填充。2026 年 11 月的市场带（第三方汇总，以官方价格页为准）：旗舰档约 $2–10 / 百万输入 token、$12–50 / 百万输出；入门档低到 $0.05–0.2 / $0.4–1.218。两个杠杆：提示缓存（系统提示与长前缀命中后打折，多轮对话的主要省钱位）与批处理（离线任务半价）。账要算到单次问答与月账单：

    上下文类：标称与有效

    厂商标称的 128K、1M 是能塞进去，不是都用得好。系统测量结论一致：相关信息落在窗口中部的准确率显著下滑10；多跳聚合类任务里，多数模型的有效上下文明显小于标称值11。长窗口还有算力账：注意力随长度平方增长，KV 缓存随长度线性增长——「把整个知识库塞进窗口」是单价最高的检索器。分工应是：在线交互保持精简（检索挑过的片段 + 必要历史），超长窗口留给离线批量消化（整库巡检、长文档对照）。

    09

    AI 推理的观测：上线之后才是开始

    OBSERVABILITY

    请求级指标看稳定性，质量级指标看答案有没有悄悄变坏——后者没有报错日志，只有观测体系能兜住。

    四类观测指标

    类别指标为什么盯它
    请求级 QPS、错误率（限流／超时／安全拒绝）、TTFT 与 tokens/s 分布、队列长度 稳定性的常规账；长尾（P99）决定最差体验
    质量级 幻觉率（抽样人评 + 模型评审并定期校准）、引用命中率、任务完成率、用户负反馈率、人工抽检覆盖率 答案质量会静默漂移：上游文档一改，模型没变、答案开始错
    成本级 单请求成本分布、提示缓存命中率、无效 token 率（重试、超长输出） 成本异动常是质量异动的先兆（模型开始绕圈子）
    安全级 PII 泄露检出、越狱与提示注入拦截率、工具权限越界调用 Agent 接了工具之后，安全指标从「加分项」变「准入项」

    链路追踪：把一次问答拆成 span

    一次 RAG 问答至少经过检索、重排、生成、安全检查四段，Agent 还要加每轮工具调用。每段记录耗时、输入输出摘要与 token 数，串成 trace，定位就从「答案不对」变成「第几段、哪个输入、什么模式」：

    span{ name:"retrieval", ms:240, docs:12, recall_probe:1.0 }
    span{ name:"rerank",　　ms:80,　kept:5 }
    span{ name:"llm",　　　 ms:7400, ttft:900, in:8.2K, out:650, cache:"hit" }
    span{ name:"grounding", ms:200,　cited:3/3 }

    制度比工具重要

    工具链相对标准：链路追踪走 OpenTelemetry 语义约定，LLM 观测用轨迹回放平台，推理引擎自带服务指标13。真正决定观测有没有用的，是三件制度性的事：每日抽检——按场景分层抽 N 条人审，幻觉率才有可信数字；负反馈进评测集——点踩的请求沉淀为回归用例，修没修有据可查；质量漂移告警——引用命中率、负反馈率的周环比突变，往往比报错更早提示「上游语料变了」。缺了这三件，面板只是更好看的仪表盘。

    10

    一页速记

    CHEATSHEET

    四张卡片带走全文：边界、杠杆、需求、指标。

    能力边界

    模型是条件概率引擎：生成强、自检弱，幻觉内生，参数知识是过期的静态快照。

    产品形态 = 可验证性 × 容错度：可验证的自动化（代码、SQL），低代价的直出（草稿），高代价的留人在环（事实与专业建议）。

    三个杠杆

    提示词改行为（分钟）→ RAG 注知识（小时至天）→ 微调塑风格（周）。

    知识放检索库，随库更新、可溯源、可下架；微调不背事实。三者共享同一份上下文预算，先算账再堆料。

    真伪需求

    真需求四条件：高频、痛点深、失败可兜底、效果可度量。

    判据是「去掉 AI 的替代成本」与「失败一次的代价」。轮子分层造：模型用 API、框架用开源，自建的只有评测集与数据飞轮。

    指标与观测

    recall@k 定能不能答，TTFT＋TPOT 定体感，token 成本定商业模型，上下文看有效值而非标称。

    上线后靠 trace＋每日抽检＋负反馈回归，质量漂移没有报错日志，只有观测兜得住。
